# ADR 0015: ブログ記事をビルド時に静的HTMLとして公開する

- Status: Accepted
- Date: 2026-08-13

## Context

`ex-foundry.com` はGitHub Pagesで配信するVite SPAであり、これまではアプリ一覧と概要ページだけを提供していた。既存の `tech-blog.s-yoshiki.com` には、個人開発したサービスや技術検証に関する記事がある。記事を移植しても、本文をブラウザのJavaScript実行後にだけ表示すると、検索クローラーや広告審査からは本文の少ないサイトとして見える可能性がある。

GitHub Pagesではサーバーサイドレンダリングを使えないため、記事のメタデータ・本文・サイトマップをビルド時に生成する必要がある。また、旧記事にはローカル画像、古い埋め込み、MDX専用コンポーネントが混在している。

## Decision

- 記事の原稿は `apps/web/content/posts` にMarkdown/MDXとして保持する。
- Markdown本文はビルド時にHTMLへ変換し、各記事の `entry/<id>/index.html` に本文を含める。
- クライアント遷移用の本文HTMLは記事ごとの静的ファイルとして生成し、初期JavaScriptバンドルへ全記事本文を含めない。
- 旧記事の画像は、公開済みの画像URLを維持できるよう `public/img`、`public/entry`、`public/images/thumbnail` に配置する。
- 記事内のスクリプト、iframe、広告ウィジェットなどの実行要素は移植時に除去し、記事本文を静的な読み物として安全に表示する。
- `/articles` を記事一覧、`/entry/<id>/` を記事詳細の正規URLとし、サイトマップへ登録する。
- 記事メタデータを扱う処理は `@repo/blog-content` に分離し、アプリから共有する。

## Consequences

記事本文がJavaScriptを実行しないクローラーにも見えるため、検索・SNS・広告審査に必要な本文とメタデータを提供できる。記事ごとのHTMLを生成するため、記事追加時はビルドが必要になる。古い記事の外部画像は相手先の提供状況に依存し、動的な埋め込みは移植後に動作しない。

全記事本文をブラウザ向けJavaScriptに含めず、記事遷移時に静的本文を取得するため、トップページの初期バンドルサイズも抑えられる。

## Alternatives considered

- **ブログを別ドメインのままリンクする**: `ex-foundry.com` 自体の本文量と主題の改善にならないため採用しない。
- **記事をそのままSPAへ埋め込む**: 初期バンドルが大きくなり、JavaScriptを実行しない取得者へ本文を提供できないため採用しない。
- **Next.jsへ全面移行する**: 静的生成は容易だが、今回のポータルの既存Vite構成とGitHub Pages workflowを大きく変更するため、まずは既存構成へビルド時生成を追加する。
