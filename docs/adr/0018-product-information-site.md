# ADR 0018: EX FOUNDRYをプロダクト情報サイトとして再構成する

- Status: Accepted
- Date: 2026-08-13
- Supersedes: [0016](0016-blog-ui-migration.md); replaces the old-asset retention described in [0015](0015-static-blog-content.md)

## Context

EX FOUNDRYには、別ドメインの `tech-blog.s-yoshiki.com` と内容が重なる技術記事が蓄積していた。複数のサイトに同じ記事を公開すると、どのサイトが現行情報を提供するのか分かりにくくなり、プロダクト本体と記事の説明がずれた場合にも訂正箇所が増える。

EX FOUNDRYは現在、DevToys Web、ひまつぶし研究室、NPB Analysis、クソゲーの森を独立したプロダクトとして公開している。サイトの役割を、一般的な技術ブログではなく、これらのプロダクトを見つけ、使い方・構成・更新内容を確認する公式情報サイトとして明確にする必要がある。

## Decision

1. `apps/web/content/posts/` は、EX FOUNDRYで現在提供しているプロダクトとサイト運用に直接関係する記事だけを公開対象にする。
2. 記事の種類を `product`、`architecture`、`release`、`operations` に分け、一覧・カード・詳細ページで分類を表示する。
3. 記事には対象プロダクトを持たせ、プロダクト紹介、技術構成、リリース情報、運用情報を横断して絞り込めるようにする。
4. `tech-blog.s-yoshiki.com` と重複する旧記事と、それらの記事だけが参照していた画像は公開ツリーから削除する。旧記事のURL互換やリダイレクトは、この再構成とは別の移行判断として扱う。
5. 記事本文はプロダクト側のREADME、architectureドキュメント、実装、公開画面を根拠に作成する。生成AIを文章整理に使用した記事は、front matterで明示し、公開前に一次資料と照合する。
6. EX FOUNDRY自体はMarkdownから静的HTMLを生成し、GitHub Pagesで配信する。プロダクト本体は要件に応じて独立した静的配信、SSR、APIを選択する。

## Consequences

プロダクト情報と別ドメインの技術ブログの役割が分かれ、利用者はEX FOUNDRYから現在利用できるサービスと、その説明・変更履歴へ移動できる。記事数を維持するより、公開中のプロダクトと結びついた具体的な情報を追加することが優先される。

一方、旧記事の公開URLは維持されないため、検索結果や外部リンクから404になるURLが発生する。検索流入や過去記事への参照を継続する必要がある場合は、旧ドメイン側の正規化・転送・公開方針を別途決定する。

記事を長くする場合も、一般論を繰り返すのではなく、対象ユーザー、入力と出力、処理場所、制約、失敗時の挙動、更新確認の方法など、利用者が判断に使える情報を増やす。仕様変更時はプロダクト紹介の現状説明と、リリース記事の履歴を分けて更新する。
