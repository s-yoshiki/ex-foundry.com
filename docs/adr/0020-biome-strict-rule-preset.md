# ADR 0020: Biomeの適用可能なルールを厳格化する

- Status: Accepted
- Date: 2026-08-18

## 背景

Biomeの既定の`recommended`プリセットは、フォーマットと基本的なlint違反を
検出できます。一方で、コードの一貫性、保守性、ブラウザ互換性を高めるルールの
多くは既定では有効になりません。

このリポジトリでは、アプリケーション・共有UI・Node.js向けのツールを同じ
workspaceで管理しています。そのため、フレームワーク専用ルールを無条件に有効に
すると、使用していないReact Native、Solid、Qwik、Vue、Svelte、Next.js向けの
誤検知が発生します。また、Biomeのprojectドメインはworkspaceのpackage exportや
ビルド前の依存関係を解決できない場合があります。

## 決定

- Biomeの汎用linterルールは`preset: "all"`で有効にする。
- 実際に使用しているReact、Vitest、Tailwind CSSのドメインは`all`で有効にする。
- 使用していないフレームワークのドメインは`none`で明示的に無効にする。
- `project`ドメインは、workspaceの解決精度を確認してから段階的に有効化する。
- 既存コードに残る高信頼ルールの違反は、ルールごとに独立した変更として修正し、
  stacked PRで順番に適用する。

## 理由

- 新しいコードに対して、Biomeが提供するルールを漏れなく適用できます。
- 使用していないフレームワーク由来の診断を品質ゲートへ混ぜません。
- ルール単位のPRに分けることで、各ルールの意図と修正範囲をレビューしやすくなります。
- projectドメインを無理に有効化して、依存関係の誤検出を品質問題として扱うことを避けられます。

## 結果

Biomeの低信頼・意見性の高いルールも診断として表示されます。既存コードの違反は
ルールごとのstacked PRで解消し、今後は新しい違反をCIで検出します。

workspaceのpackage exportとビルド成果物をBiomeが正しく解決できる状態になったら、
`project`ドメインを再評価します。
