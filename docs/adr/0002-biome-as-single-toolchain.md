# ADR 0002: FormatterとLinterをBiomeに一本化する

- Status: Accepted
- Date: 2026-07-27

## 背景

ESLintとPrettierを併用する構成は広く使われていますが、
責務が重なる部分（インデント、引用符、セミコロン）の設定衝突を避けるために
連携プラグインが必要になり、設定ファイルとプラグインの依存が増えます。

## 決定

BiomeをFormatterとLinterの唯一の基盤とし、ESLintとPrettierを併用しません。

## 理由

- 1つのツールが両方を担当するため、責務の重複による設定衝突が起きません。
- 設定が`biome.json`の1ファイルに収まり、プラグイン依存がありません。
- CIでの実行が速く、`pnpm check`で差分とlint違反を同時に確認できます。
- 除外設定を1か所（`biome.json#files.includes`）に書けます。

## 検討した代替案

- **ESLint + Prettier**: エコシステムは最大ですが、
  この規模では設定量と実行時間に見合いません。
- **oxlint**: 速度は魅力的ですが、フォーマット機能を別途用意する必要があります。

## 結果

`pnpm check` / `pnpm check:fix`だけを覚えれば、書式とlintの両方を扱えます。

ESLint専用ルールに強く依存したいケースが出た場合は、
ルール全体を無効化するのではなく、対象pathへoverrideを設定して対処します。
それでも足りなくなったら、このADRを置き換えます。
