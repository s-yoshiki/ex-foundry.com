# ADR 0019: 記事に実装例と構成図を含める

- Status: Accepted
- Date: 2026-08-13
- Supersedes: なし

## Context

EX FOUNDRYの記事は、プロダクトの目的、現在の仕様、技術構成、リリース内容を公式情報として説明する。文章だけでは、ブラウザとAPIの境界、データの流れ、描画方式の選択理由など、複数の責務が関係する説明を追いにくい場合がある。

また、構成記事でコードをまったく示さないと、説明が実装とどう対応するかを読者が確認しにくい。一方、実装からコードを大量に転載すると、プロダクト側の変更で記事が古くなりやすく、別ドメインの技術ブログとの役割も重なりやすい。

## Decision

1. 実装の境界やデータの流れを説明する記事には、記事専用のSVG図を必要な範囲で添付する。SVGは記事ディレクトリに置き、外部画像サービスや実行時スクリプトへ依存しない。
2. コードブロックは、入力・出力・責務の境界を具体化するために使用する。実装から抜粋したコードでない場合は「説明用の簡略例」と明記し、実際のプロダクトコードとの完全一致を約束しない。
3. 記事の画像アセットはMarkdownから相対参照し、ビルド時に記事URLのディレクトリへコピーする。許可する形式は既存の `PostAsset` が扱う静的画像形式に限定する。
4. 図とコードは、プロダクトの利用判断、データの送信先、処理場所、失敗時の挙動、構成の選択理由を補足する場合に追加する。文字数を増やすだけの装飾や、実装と無関係な一般論は追加しない。

## Consequences

読者は、説明文と図・コードを対応づけながら、プロダクトがどこで処理し、どの境界を越えるかを確認できる。記事専用のSVGはGitHub Pagesから同一ドメインで配信されるため、第三者サービスの停止やトラッキングに影響されない。

一方、構成や仕様が変わると図とコード例も更新が必要になる。記事の変更時には、プロダクト側の一次資料と公開画面を照合し、説明用コードであること、データを保存・送信する範囲、図の矢印が示す責務を確認する。SVGの追加だけでは記事の有用性が増えないため、必ず本文の判断や制約と結びつける。
