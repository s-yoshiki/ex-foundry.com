# 技術ブログのUIと情報設計をex-foundryへ統合する

- Status: Accepted
- Date: 2026-08-13
- Supersedes: なし

## Context

`tech-blog.s-yoshiki.com` の記事本文を `ex-foundry.com` へ移植したことで、記事データは同じサイトで配信できるようになった。一方、トップページと記事一覧は移植前のアプリケーション一覧を中心としたUIのままであり、記事の量や分類を訪問者へ伝えにくかった。

AdSenseの審査で「有用性の低いコンテンツ」と判断される可能性を下げるには、記事本文だけでなく、サイトの目的、運営者、記事の分類、継続的な更新が明確に確認できる情報設計が必要である。また、GitHub Pagesで静的HTMLを直接配信する構成は維持する必要がある。

## Decision

- トップページを技術記事を中心としたブログホームに変更し、新着記事、よく読まれている記事、タグ、月別アーカイブ、運営者情報を表示する。
- 記事カード、検索、タグ、アーカイブはReactのSPA表示とViteの静的HTML生成で同じ構成を提供する。
- 既存のアプリケーション一覧は `/apps/` に分離し、ヘッダーとトップページから到達できるようにする。
- 移植元の余白、カード、境界線、テーマ切り替え、レスポンシブな最大幅レイアウトをTailwindの既存デザイントークンで再現する。
- 記事の検索・タグ・年月の絞り込みはURLクエリに保持し、共有可能な状態にする。

## Consequences

- トップページで記事の専門性とサイトの運営主体を説明でき、記事間の回遊導線も増える。
- `/apps/` の追加により、アプリケーション一覧と技術記事の目的を分離できる。
- 記事データからタグとアーカイブを算出するため、記事を追加しても一覧側のメンテナンスが不要になる。
- UIの構成が静的生成側にも存在するため、表示変更時はReactコンポーネントとViteプラグインの両方を確認する必要がある。
