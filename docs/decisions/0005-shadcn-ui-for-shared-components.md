# 0005. 共有UIをshadcn/uiベースで構築する

- 状態: Accepted
- 日付: 2026-07-27

## 背景

共有UIを完全に自作すると、フォーカス管理・キーボード操作・ARIA属性を
すべて自前で実装・検証することになります。実際、初期実装の
セグメント切り替えはbuttonと`aria-pressed`の組み合わせで、
ラジオグループとしてのキーボード操作を持っていませんでした。

一方で、スタイル込みのUIライブラリを導入すると、
デザインを変えるためにライブラリのAPIと戦うことになります。

## 決定

shadcn/uiを共有UIの土台とし、生成されたコンポーネントを
`packages/ui/src/components/ui/`へ取り込みます。
その上に、アプリの語彙に合わせた合成コンポーネントを置きます。

## 理由

- Radix UIのプリミティブがアクセシビリティの難所（ロービングフォーカス、
  ARIA属性、キーボード操作）を引き受けます。
- コードがリポジトリへコピーされるため、
  ライブラリのバージョンに縛られずに変更できます。
- スタイルはTailwindのutilityとして書かれており、
  [0004](0004-tailwind-css-first-configuration.md)のトークン方針と一致します。

## 検討した代替案

- **自作プリミティブ**: 依存は最小ですが、
  アクセシビリティの実装と検証コストを継続的に負担します。
- **MUI / Chakra**: 完成度は高いものの、
  独自のテーマシステムとスタイル基盤を持ち込むことになります。
- **Radix UIを直接使う**: shadcn/uiは実質これに定型のスタイルを付けたものです。
  CLIで雛形を得られる分、shadcn/uiの方が立ち上がりが速いです。

## 結果

`components/ui/`はCLIの再生成対象として扱い、
振る舞いを変える変更はラッパー側へ書きます。

生成コードのimportは、path aliasではなくパッケージ名の
self-reference（`@ex-foundry/ui/lib/utils`）で解決します。
`@/`エイリアスにすると、共有UIを使うapp側にbundlerとtsconfigの
alias設定を強いることになるためです。

Radixのプリミティブは素のHTMLと異なるroleを描画することがあります
（`ToggleGroup type="single"`は`radiogroup`/`radio`）。
テストは実際のroleに合わせて書きます。
