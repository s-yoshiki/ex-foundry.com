# Repository guide

This repository is the reference pnpm/Turborepo layout for ex-foundry projects.

## Layout

- Run commands from the repository root.
- Use Node.js 26 and the pinned pnpm version.
- Applications belong in `apps/*`.
- Shared tool configuration belongs in `configs/*`.
- Shared source packages belong in `packages/*`.
- Infrastructure and repository-local CLI tools belong in `scripts/*`.
- Keep framework-specific code inside its application.
- Packages must never import from an application.
- Do not edit generated directories such as `dist`, `.turbo`, or `node_modules`.

## Frontend

- Split `apps/*/src/features/<feature>/` by user-facing capability, not by
  technical layer. Scaffold one with `pnpm create:feature <name>`.
- Global hooks that are not tied to a single feature belong in
  `apps/*/src/hooks/`. Domain-independent utility functions and types belong
  in `apps/*/src/libs/`. Keep feature-specific hooks and functions inside
  their feature's own `hooks` / `functions` directory.
- Check `@repo/ui` before writing a new component. Add shadcn primitives
  with `pnpm --filter @repo/ui ui:add <name>`.
- Style with Tailwind utility classes; do not introduce bespoke CSS classes.
- Add shared design tokens to `configs/tailwind-config/theme.css` only.
  Themes switch via the `data-theme` attribute, not a class.
- Files under `packages/ui/src/components/ui/` are regenerated by the shadcn
  CLI. Wrap them instead of rewriting them.

## API

- Keep API routes in `apps/api` and keep handlers thin.
- Request and response shapes live in `packages/api-contract`. Change the
  contract first, then the server, then the client.
- Validate every external input (HTTP, storage, environment) at its boundary.
- Never leak stack traces, secrets, or rejected input back to the caller.

## Tests

- Vitest is the only test runner. Place tests next to what they cover.
- Cover the failure paths, not just the happy path.
- Query by role and label rather than by test id or class name.

## Documentation

- Docs are written in Japanese; code and code comments in English.
- Record structural decisions in `docs/decisions/` before implementing them.

Before hand-off, run:

```sh
pnpm check
pnpm typecheck
pnpm test
pnpm build
```
